###### 3. Independent authoritative contracts

A 'contract' is a machine-readable rule sheet stating precisely:

- Which fields are mandatory;
- The type of each field;
- Which fields cannot be empty;
- Whether the model may add other fields;
- The shape of every array item.

For example, create:

```text
contracts/discovered_schema.schema.json
```

With rules like:

```json
{
  "type": "object",
  "properties": {
    "vertical": {
      "const": "private_health"
    },
    "fields": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "name": {"type": "string"},
          "values": {
            "type": "array"
          }
        },
        "required": ["name", "values"],
        "additionalProperties": false
      }
    }
  },
  "required": ["vertical", "fields"],
  "additionalProperties": false
}
```

'Independent' means stored separately in `contracts/`, rather than hidden in a prompt or Python function.

'Authoritative' means the sole standard:

```text
                         ┌─ OpenAI Structured Outputs
JSON Schema 契约文件 ────┼─ Anthropic Structured Outputs
                         ├─ DeepSeek prompt + JSON mode
                         ├─ 本地输出验证
                         ├─ 自动重试错误信息
                         └─ 单元测试与 API 文档
```

Everywhere reads the same rules. We cannot have:

- A prompt saying `values` is optional;
- A Python validator saying it is mandatory;
- A README example using `null`;
- An OpenAI request using a fourth definition.

This is a 'single source of truth,' which can be understood as the 'one standard answer.'

###### 4. Python Domain Model

This is another way to store the 'one standard answer.'

Instead of hand-writing `contracts/discovered_schema.schema.json`, define in Python:

```python
class SchemaField:
    name: str
    values: list[str]
```

Then automatically generate JSON Schema from the Python model.

So the main difference between 3 and 4 is:

| Approach | Where the sole standard lives |
|---|---|
| 3: Contract-first | `contracts/*.schema.json` |
| 4: Domain-model-first | Python class/model |

I favor approach 3 because your schemas are themselves core research artifacts. Independent JSON files are easier for team members to inspect and discuss without understanding Python classes.
