### [2026-08-10T14:05:23.740Z] Codex

In this project, the two most common approaches are:

**Temporarily load it into the current terminal environment:**

```bash
set -a
source .env
set +a
```

Then check a variable:

```bash
echo "$OPENAI_API_KEY"
```

`set -a` automatically exports variables defined in `.env`, allowing subprocesses such as `python src/run.py ...` to read them.

**Load `.env` for a single command only:**

```bash
env $(grep -v '^#' .env | xargs) .venv/bin/python src/run.py --help
```

However, this method is unreliable for spaces, quotes, and multiline values. The first approach is recommended.

This `.env` format works:

```bash
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4.1-mini
```

Do not commit `.env` to git. Project instructions also explicitly prohibit exposing API keys.
